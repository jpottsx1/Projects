Send to ImageOptim

Support for the macOS Finder Quick Action that sends your selected images straight to ImageOptim.

Get support

Questions, bug reports and feature requests all go to the issue tracker. It is the support address for this project, and it is read by a person.

Support website: https://github.com/jpottsx1/Projects/issues

Before opening an issue, run send-to-imageoptim --check in Terminal and paste its full output — it names the copy of ImageOptim that was found, its bundle identifier, and which handoff method the app accepted. That output answers most of what would otherwise be a round of questions.

What it does

Select images in Finder, right-click, Quick Actions → Send to ImageOptim, and they land in ImageOptim's queue exactly as if you had dropped them on its window. No drag-and-drop, no dragging a folder onto the Dock icon.

ImageOptim has no scripting interface, so the files are handed over the way a drop does: an "open documents" Apple Event sent straight to the app. If that is refused, the script falls back through three cruder routes, in order — the same event addressed by name, open -a, and finally relaunching the app with the paths in its argv.

Requirements

  • macOS — tested on Ventura and later; the Services mechanism itself is far older.
  • ImageOptim.app installed.

Install

One script, nothing else needed:

./setup.sh

It writes the command to ~/.local/bin, installs the Quick Action that calls it, refreshes the Services cache, and then sends ImageOptim a test image it creates itself, reporting which handoff method worked. ./setup.sh --uninstall removes both.

Then, in Finder: select some images → right-click → Quick Actions → Send to ImageOptim. Older macOS versions list it under Services instead.

Anything elsesilently skipped

ImageOptim rewrites files in place. It is lossless by default, but if you have configured lossy settings inside ImageOptim, the originals are gone. Keep that in mind before pointing it at a folder of masters.

Configuration

Create ~/.config/send-to-imageoptim/config. It is sourced by the script, so no rebuild or reinstall is needed after a change: 

# only touch bitmaps, leave SVGs alone
IMAGEOPTIM_EXTS="png jpg jpeg gif"

# a copy of ImageOptim somewhere unusual
IMAGEOPTIM_APP="$HOME/Applications/ImageOptim.app"

# no notification when a selection has nothing to optimize
IMAGEOPTIM_QUIET=1

# pin the handoff instead of trying applescript, launchargs, openapp in order
IMAGEOPTIM_METHOD="applescript"

The same names work as environment variables and take precedence over the config file.

Troubleshooting

Start with send-to-imageoptim --check. It prints which ImageOptim it found and its bundle identifier, then sends it a 1×1 PNG it writes itself — no path for you to get wrong — and reports which of the four handoff methods was accepted.

The menu item never appears.
Services are cached. Run killall Finder, then check System Settings → Keyboard → Keyboard Shortcuts → Services → Files and Folders and tick Send to ImageOptim. That is also where you can give it a shortcut such as ⌃⌥⌘O. Confirm the bundle is at ~/Library/Services/Send to ImageOptim.workflow.
"ImageOptim is not installed."
The script asks LaunchServices for the app by name, then looks in /Applications and ~/Applications. If ImageOptim lives elsewhere, or Spotlight indexing is off for that volume, set IMAGEOPTIM_APP in the config file.
"ImageOptim cannot open files in the PNG image format" — and --check says a method was accepted.
More than one app ships as "ImageOptim". The one on the Mac App Store (com.luoxiao.ImageOptim) declares no document types at all and takes files by drag-and-drop only: it accepts the Apple Event, then refuses the file with that dialog. Nothing in this script can work around an app with no way in. Get the real one and pin it: 
mv /Applications/ImageOptim.app "/Applications/ImageOptim (App Store).app"
brew install --cask imageoptim
mkdir -p ~/.config/send-to-imageoptim
echo 'IMAGEOPTIM_APP="/Applications/ImageOptim.app"' > ~/.config/send-to-imageoptim/config
--check prints the bundle identifier it resolved and warns when it is not net.pornel.ImageOptim.
Both applescript rungs are refused.
macOS gates Apple Events between apps. Allow the sender — Terminal for command-line use, Automator for the Quick Action — under System Settings → Privacy & Security → Automation. Without it the script still works, one rung down.
Nothing happens and no notification appears.
Notifications for Script Editor / Automator may be muted in System Settings → Notifications. Run the same selection through send-to-imageoptim in Terminal to see the error text directly.
Still stuck.
Open an issue at https://github.com/jpottsx1/Projects/issues with the full --check output, your macOS version, and how ImageOptim was installed.

Uninstall

./setup.sh --uninstall

Removes the Quick Action from ~/Library/Services and the installed command. The config file, if you made one, is left alone.
